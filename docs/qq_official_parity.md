# QQ 官方机器人与 OneBot 功能对齐

本轮沿用 DecisionHub、MessageMixin 和 ToolNet，修复共享链路中的平台假设。

## 本轮变化

- 官方用户和群 OpenID 保持字符串，包括只有数字、带前导零的标识。
- 官方命令按原 OpenID 检查权限，未配置的 `0` 不再匹配超管；数字 QQ 的环境变量仅用于 OneBot。
- 群命令通过原群消息回复；C2C 使用私聊会话，频道和频道私信保留各自的 SDK 回复方法。
- 官方回复携带原 `msg_id`，同一回复中的分片共享递增序号。
- 平台适配器和 AI 工具上下文按异步请求隔离；找不到匹配通道时，不将官方 OpenID 交给 OneBot。
- 官方端使用共享的记忆、知识库、天气、定时任务等业务工具；模型工具清单过滤当前适配器未实现的点赞、戳一戳、成员查询和群文件接口。
- 官方机器人可对频道消息添加表情回应，默认使用当前频道与触发消息；群聊/C2C 表情回应、点赞和戳一戳未开放给官方工具清单。
- OneBot 点赞、戳一戳和消息表态按 API 返回状态报告结果；明确失败或超时不会显示为成功。
- 工具执行保留当前请求的记忆引擎、调度器和平台信息，不依赖惰性子网的默认组件。
- 仅启动官方平台也能初始化调度器；提醒保留原群/用户 OpenID，跨线程投递回到平台所在事件循环。
- 图片、视频和 Silk 语音使用文件内容上传，再用返回的 `file_info` 发送富媒体消息。收到消息回执后才报告成功。
- 附件下载放到工作线程，图片/文件分类不会重复下载同一个附件。
- 共享 TTS 调用官方语音发送实现；转码操作使用临时副本，失败则回复文字。

## 生效与限制

重启弥娅服务后加载这批代码，无需新增配置项。身份互通仍使用已有明确绑定，不自动推测 QQ 号与 OpenID 的对应关系。

当前适配器的出站媒体类型仍为 JPG/PNG、MP4 和 Silk。其他格式不能因基类存在文件发送方法，就视为已支持。

当前虚拟环境没有 `pilk`。MP3/WAV 转 Silk 需要可用的编码依赖；缺失时会回退文字。已有 Silk 文件的上传和发送链路已用模拟 API 验证。

接口权限、主动消息额度和回复限制由 QQ 平台决定。代码测试使用模拟 SDK/API，不代表真实账号已通过在线验收。

## 真实账号验收

1. 群中 `@机器人 /help`，确认只在原群回复；C2C 私聊 `/help`，确认在原私聊回复。
2. 在两个群同时提问，确认各自上下文及回复目标独立。
3. 查询天气、添加与查询记忆、查询知识库，确认工具实际执行。
4. 群聊和私聊各创建一次短时文字提醒，确认目标、所属平台和实际投递结果。
5. 发送带问题的图片，确认识别；要求发送一张本地 PNG/JPG，确认客户端实际收到图片。
6. 准备好编码依赖后开启语音模式，确认收到语音；模拟转码失败时确认回退文字。
7. 频道消息中请求添加系统表情或标准 Emoji，确认 SDK 使用当前频道和消息 ID；群聊/C2C 请求时确认明确提示暂不支持。

针对上述问题的自动回归位于 `tests/test_qq_official_parity.py`，全部使用隔离依赖和模拟投递，不会向真实账号发送消息。
